# تنسيق الواجهات وفحص وظائف الخلفية

## التصميم

- الصيدلية: ثيم مشترك يحافظ على الأزرق الموجود في التطبيق، مع نوافذ وبطاقات بيضاء وحدود خفيفة وحقول مستديرة. أزيل لون Material 3 البنفسجي الافتراضي.
- نافذة العرض الجزئي والتبديل: دمج الصورة مع اسم الصنف، أدوات كمية واضحة، وإجمالي بارز. نفس التنسيق في اختيار البديل وقرارات الطلب.
- المستخدم: بطاقات العروض تتبع لوحة ألوان البحث، مع زر قبول أزرق وإبقاء لون الإلغاء والتنبيهات دالًا على الحالة.
- الصور المفقودة تبقى أيقونة دون عبارة.

التعديلات محلية وتحتاج بناء التطبيقين لتظهر؛ لا توجد عملية نشر ضمن هذا العمل.

## أمر الفحص — PowerShell

```powershell
Set-Location 'C:\Users\hp\StudioProjects\user_application'
$env:Path = "C:\Program Files\nodejs;$env:Path"
node --use-system-ca functions/scripts/check-deployed-backend.cjs
```

للوظائف السبع المرتبطة بإصدار مسارات الطلبات فقط:

```powershell
node --use-system-ca functions/scripts/check-deployed-backend.cjs --orders
```

الأداة تقرأ Firebase ولا تنشر. تطبع أمر نشر مسمى للوظائف ذات الحزمة المختلفة أو المفقودة، لينفذه المستخدم بعد المراجعة. تستخدم خوارزمية Firebase CLI نفسها لترتيب الملفات والبصمة.

- `MATCH`: بصمة الحزمة والبيئة المحلية وruntime متطابقة مع المنشور.
- `SOURCE_DIFF`: الحزمة أو runtime مختلف. Firebase يحسب بصمة **الحزمة كاملة**، بما فيها الاختبارات والأدوات غير المستثناة؛ هذا لا يثبت أن سلوك كل وظيفة تغير.
- `MISSING`: الوظيفة المحلية غير منشورة في المنطقة المحددة.
- `UNKNOWN`: لم يمكن التحقق، ولا تُعامل كنسخة مطابقة.

رموز خروج الأداة: 0 مطابق، 2 اختلاف/وظيفة مفقودة، 3 حالة غير قابلة للتحقق، 1 تعذر الفحص.

النطاق: Cloud Functions من الجيل الثاني في codebase `default`. لا يقارن قواعد Firestore/Storage أو الفهارس أو خدمة Flask أو ملفات بناء الهاتف/الصيدلية. مقارنة البيئة تستخدم إعداد Firebase المسجل في الوظيفة المنشورة مع ملفات البيئة المحلية؛ ليست فحصًا لتغير إعدادات المشروع العامة أو قيم الأسرار.

## نتيجة الفحص أثناء التعديل

- وظائف مسار الطلبات السبع: حزمة المصدر تختلف عن المحلية.
- الفحص الشامل: 35 وظيفة بحزمة مختلفة، و`getPharmacyReport` غير منشورة.
- لا تعني هذه الأعداد وجود 35 تغييرًا مستقلًا في السلوك. استخدم `--orders` عند نشر إصدار مسارات الطلبات المحدد، والفحص الكامل لمراجعة الخلفية الأوسع.

## التحقق

- اختبارات واجهات المستخدم: 5 ناجحة.
- اختبارات نافذة تبديل الصنف وبطاقات الصيدلية ومعاينة الثيم: 4 ناجحة.
- اختبارا فحص النشر: ناجحان، بما فيه مقارنة البصمة الناتجة مباشرة بخوارزمية تجهيز الحزمة في Firebase CLI.
- تحليل ملفات الصيدلية المعدلة: دون أخطاء. تحليل المستخدم: دون أخطاء، مع 5 ملاحظات سابقة عن `withOpacity`.
